# poc `mockup` plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a `mockup` plugin for poc. Agents write JSON mockup descriptions, a ratatui viewer renders them in a dedicated `mockup-<agent>` tmux view, and the operator's terminal is switched there and back automatically.

**Architecture:** A new crate, `poc/plugins/mockup` (`tx-mockup`), split into a pure layer and a UI layer.
- **Pure layer:** `model` (JSON → `Screen`), `markup` (`[green]…[/]` → ratatui `Line`), `render` (`Screen` → `Buffer`), and `viewer` (a state machine plus the terminal loop).
- **UI layer:** `lib.rs`, with the verbs and the view/client switching through `tx_ui::tmux::Ui`.

A skill and an `agents/COMMON.local.md` overlay ship as resources.

**Tech Stack:** Rust 2024, `ratatui = "0.30"` and `crossterm` (the version ratatui 0.30 re-exports, used through `ratatui::crossterm`), serde/serde_json, and tmux.

**Spec:** `docs/superpowers/specs/2026-10-19-tx-mockup-design.md`

## Global Constraints

- Work in `poc/` (its own workspace). These must pass after every task: `cargo test --workspace`
  and `cargo clippy --workspace --all-targets -- -D warnings`. Tmux tests use `require_tmux!` and
  the `tx-core-cli/tests/common` `Cli` harness (temp state dir, private socket).
- Every tmux call goes through `tx_ui::tmux::Ui` (`-S <socket> -f <state_dir>/tmux.conf`). Never
  touch the user's default server.
- No change to `tx-core` (D2). No call into another plugin's Rust code at run time (D3).
- Option names are hyphenated: `@tx-view`, `@tx-mockup-return`, `@tx-mockup-dir`,
  `@tx-mockup-client`.
- Plugin id: `mockup`. Crate: `tx-mockup`. Verb names never shadow `RESERVED` in
  `tx-core-cli/src/plugins.rs`. `show`/`stop` are sub-arguments of the `mockup` verb, so that's fine.
- The viewer never panics on a bad file. It keeps the last good screen and shows the error in
  the bottom bar in `WARN` colour (rgb 224,175,104, from `tx_ui::render::WARN_ANSI`).
- Session dir: `<project>/.superpowers/mockup/<agent-session-id>/{content,state}/`. Events go to
  `state/events` (JSON lines).
- View name: `mockup-<agent-name>`.

## Review Focus

1. **A file caught mid-write.** The agent's Write tool produces a truncated JSON file, the
   viewer reads it, and parsing fails. Expected: the error bar shows, the last good screen
   stays up, and the full file loads on the next poll once its mtime or length changes
   (Task 4: `half_written_file_then_complete_loads`).
2. **Pressing `1`–`9` past the last option.** Expected: nothing happens and no event is written
   (Task 4: `select_out_of_range_is_ignored`).
3. **`show` with no operator client attached** (headless agent). Expected: it prints
   `mockup ready in view mockup-<name>` and exits 0 (Task 5: `show_without_client_prints_ready`).
4. **`show` after the view was killed.** Expected: the view is recreated from
   `ext["mockup"].dir` and the viewer is running again (Task 5: `show_recreates_dead_view`).
5. **A tiny terminal** (for example 20x5) with three side-by-side options. Expected: rendering
   doesn't panic. Layout may clip (Task 3: `tiny_area_does_not_panic`).

### Task 1: Crate scaffold + description model

**Files:**

- Modify: `poc/Cargo.toml` (add `plugins/mockup` to `members`)

**Interfaces — Produces** (`tx_mockup::model`):
```rust
pub struct Screen { pub title: Option<String>, pub sub: Option<String>, pub fps: u32 /* default 8 */,
                    pub options: Vec<Choice>, pub body: Option<Node> }
pub struct Choice { pub id: String, pub title: String, pub note: Option<String>, pub body: Node }
pub struct Node { pub size: Size, pub kind: Kind }
pub enum Size { Len(u16), Pct(u16), Fill }            // 7 | "30%" | absent
pub enum Kind { Row(Vec<Node>), Col(Vec<Node>), Block { title: String, body: Box<Node> },
                Text(String), List { items: Vec<String>, sel: Option<usize> },
                Table { head: Option<Vec<String>>, rows: Vec<Vec<String>> },
                Frames { frames: Vec<String>, fps: Option<u32> } }
pub fn parse(text: &str) -> Result<Screen, ParseError>;   // ParseError: Display = one line, e.g. "line 3 col 9: …"
```
JSON keys follow the spec's sketch: `title` `sub` `fps` `options[{id,title,note,body}]` `body`;
node keys `size` plus exactly one of `row` `col` `block`(+`body`) `text` `list`(+`sel`)
`table`(+`head`) `frames`(+`fps`). Deserialize into a raw struct of optional fields, then
convert. Both `options` and `body` present, or neither, is an error. `lib.rs` for now: `pub mod
model;` plus `MockupPlugin` (id `mockup`) whose `register` adds nothing yet.

`Cargo.toml` deps: `tx-core`, `tx-ui`, `serde`, `serde_json`, `thiserror`, `ratatui = "0.30"`
(enable its crossterm feature, which is the default). Dev: `tempfile`.

### Task 2: Markup → ratatui lines

**Files:** Create `poc/plugins/mockup/src/markup.rs`. Modify `lib.rs` (add `pub mod markup;`).

**Interfaces — Produces:** `pub fn lines(text: &str) -> Vec<ratatui::text::Line<'static>>`.
It never fails: an unknown or unclosed tag renders literally.

Grammar: `[spec]` opens a style and `[/]` closes the innermost one. Styles stack. `[[` is a
literal `[`. `spec` is space-separated tokens:
- modifiers: `bold` `dim` `italic` `reverse` `underline`;
- colours: `black red green yellow blue magenta cyan white gray`;
- palette names: `accent` = rgb(122,162,247), `warn` = rgb(224,175,104), `fg` = rgb(192,202,245),
  `info` = rgb(125,207,255) (the `tx_ui::render` constants);
- `on <colour>` sets the background.

If any token is unknown, the whole `[...]` is literal text. `\n` splits lines.

  - `on_background`: `"[bold yellow on blue]x[/]"`.

### Task 3: Rendering a screen into a buffer

**Files:** Create `poc/plugins/mockup/src/render.rs`. Modify `lib.rs` (add `pub mod render;`). This
task needs `markup::lines`. When it runs in parallel with Task 2, add a temporary private
`fn lines` shim and swap it for the real one when the two are merged.

**Interfaces:**
- Consumes: `model::*`, `markup::lines`.
- Produces:
```rust
pub enum Layout { All, One }                       // Tab toggles; All = options side by side
pub struct ViewState { pub focus: usize, pub selected: Option<usize>, pub layout: Layout,
                       pub error: Option<String>, pub waiting: bool }
pub fn draw(screen: &Screen, state: &ViewState, elapsed: std::time::Duration,
            area: ratatui::layout::Rect, buf: &mut ratatui::buffer::Buffer);
```
- Layout:
  - **Top:** title in bold, then `sub` in dim.
  - **Bottom line:** if `state.error` is set, the error in warn colour; otherwise the hint
    `1-9 pick · ←/→ move · tab layout · enter confirm · esc back`.
  - **Middle:** options. `All` splits them horizontally, equally. `One` shows `options[focus]`.
  - Each option is a bordered block titled `A · <title>` (letter = index), with `note` as its
    last line in dim.
  - The selected option has an accent border and a `✓` in its title. The focused one has a bold
    border.
  - `waiting` draws only the centered dim text `continuing in terminal…`.
- Frames: index = `(elapsed_ms * fps / 1000) % frames.len()`, where `fps` = node fps, else
  screen fps.
- `Size` maps to `Constraint::Length` / `Percentage` / `Fill(1)`.
- `List` highlights `sel` with reverse video.
- Text uses `markup::lines`.

### Task 4: Viewer — reload, keys, events, terminal loop

**Files:** Create `poc/plugins/mockup/src/viewer.rs`. Modify `lib.rs` (add `pub mod viewer;`).

**Interfaces:**
- Consumes: `model::parse`, `render::{draw, ViewState, Layout}`.
- Produces:
```rust
pub enum Action { None, Back }                      // Back = switch the operator back
pub struct Viewer { /* content_dir, events_path, current: Option<(PathBuf, SystemTime, u64 len)>,
                       screen: Option<Screen>, state: ViewState, started: Instant */ }
impl Viewer {
    pub fn new(session_dir: &Path) -> Self;         // content/ and state/ under it; creates both
    pub fn poll(&mut self) -> bool;                 // true when the screen changed
    pub fn key(&mut self, code: ratatui::crossterm::event::KeyCode) -> Action;
    pub fn draw(&self, area: Rect, buf: &mut Buffer);
}
pub fn run(session_dir: &Path, on_back: impl FnMut()) -> std::io::Result<()>;
```
- `poll` picks the newest `*.json` in `content/` by mtime. It re-reads when the path, mtime or
  length changes.
- A filename starting with `waiting` sets `state.waiting = true` without parsing.
- A new path resets `focus`/`selected`/`started`, clears `state.error`, and truncates
  `state/events`.
- A parse error sets `state.error = "<file>: <ParseError>"` and keeps the old `screen`.
- Keys:
  - `1`–`9`: select. If it's in range, set `selected` and `focus`, and append `select`.
  - `←`/`h` and `→`/`l`: move focus, wrapping.
  - `Tab`: toggle layout.
  - `r`: reset `started`.
  - `Enter`: append `confirm` (with the selected choice, if any) and return `Back`.
  - `Esc`/`q`: append `dismiss` and return `Back`.
- Event line:
  `{"type":"select"|"confirm"|"dismiss","choice":id|null,"title":t|null,"screen":"<file name>","timestamp":<unix secs>}`.
- `run` handles terminal setup and restore with `ratatui::init()` / `ratatui::restore()`. It
  loops: poll about every 200ms, draw at the screen fps (at least 4, at most 30), handle keys,
  and call `on_back` on `Back`. The viewer keeps running; only the verb decides to stop it.

**Files:**

  plugin list or help text

- Test: create `poc/tx-core-cli/tests/mockup.rs`

**Interfaces:**
- Consumes: `viewer::run`.
- Produces, in `txc` help:
  - `mockup start --project DIR [--for S] | show [--for S] | wait [--for S] | stop [--for S]   ratatui mockups for brainstorming`
  - `_mockup-view <session_dir> <view>   the viewer (internal)`

Behaviour:
- **Resolving the agent:** `--for <name|id>` via `core.resolve`. Otherwise use `$TX_SESSION_ID`,
  but only when `$TMUX`'s socket equals `core.socket_path()` (copy `sender_from_env`'s rule from
  `tx-core-cli/src/main.rs:187`). Otherwise exit 2 with `txc mockup: no agent session (use --for)`.
- **`start`:** create `<project>/.superpowers/mockup/<agent-id>/{content,state}`. Store
  `ext["mockup"] = {"dir": "<abs session dir>"}` via `core.update_ext`. Ensure the view, then
  print `{"view":…,"content_dir":…,"state_dir":…}` and a newline.
- **Ensure view** (copy `ensure_home` in `plugins/ide/src/install.rs:368`): if
  `mockup-<name>` is missing, create it with `new-session -d -s <view> -c <project>` running
  `<current_exe> --state-dir <state> _mockup-view <dir> <view>`. Then set `@tx-view 1`,
  `@tx-mockup-dir <dir>` and `status off`.
- **`show`:**
  1. Read the dir from ext. If it's missing, exit 1 with `txc mockup: run 'txc mockup start' first`.
  2. Ensure the view.
  3. Find the outer client. Of `list-clients -F '#{client_name}\t#{client_session}\t#{client_activity}'`,
     candidates are clients whose session is the agent, or is a host in `ui.attached_to(agent)`.
     Hosts are followed transitively, a view inside a view. Exclude clients whose session starts
     with `mockup-`. Pick the highest `client_activity`. Put this choice in a pure
     `fn pick_client(clients: &str, agent: &str, hosts: &[String]) -> Option<(String, String)>`
     that returns (client, session).
  4. If there's none, print `mockup ready in view <view>` and exit 0.
  5. Otherwise set `@tx-mockup-return <session>` and `@tx-mockup-client <client>` on the view,
     then run `switch-client -c <client> -t =<view>`.
- **`wait`:** write `content/waiting-<unix_millis>.json` containing `{}`. No switch.
- **`stop`:** kill the view (`ui.kill_session`). Exit 0 even when it's already gone.
- **`_mockup-view`:** `viewer::run(dir, on_back)`. `on_back` reads `@tx-mockup-client` and
  `@tx-mockup-return` from the view and runs `switch-client -c <client> -t =<return>`, best effort.
