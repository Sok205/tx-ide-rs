# tx-core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new workspace crate `poc/tx-core` that runs and manages a swarm of interactive agents on tx's own tmux server, plus two engine crates and a thin CLI, every line covered by tests.

**Architecture:** `TxCore` is one plain struct owning a store, a tmux wrapper bound to a private socket and config, an event log, an engine registry, profile search dirs and a lock directory. Disk is the record; tmux holds only the `@tx-id` link; `$N`/`%N` targets are looked up by `@tx-id` on demand. Engines are `Box<dyn EngineAdapter>` with a pure `launch`.

**Tech Stack:** Rust 1.92 (edition 2024, `std::fs::File::lock`), `serde`/`serde_json`, `thiserror`, `uuid` v4, `tempfile` (atomic record writes). No new dependency beyond what `crates/tx` already uses. tmux ≥ 3.2 (`new-session -e`), tested against 3.6a.

**Spec:** `docs/superpowers/specs/2026-10-15-tx-core-design.md`

## Global Constraints

- Workspace lints: `[lints] workspace = true` → `clippy::all = warn`; CI command is `cargo clippy --all-targets -- -D warnings`, so zero clippy warnings.
- The library never parses argv and never reads the process environment. `CoreConfig` carries everything. Only the CLI crate touches `std::env`.
- Every tmux invocation is `tmux -S <socket> -f <config> …`. Nothing ever reaches the user's default server.
- Socket path limit: `open` fails with `SocketPathTooLong` when the path is **> 100 bytes**, before creating any file.
- Session name grammar: `[A-Za-z0-9_-]+`.
- `Exited` and `Stopped` are terminal. No operation revives a record.
- `list-sessions` failure other than "no server" is `TmuxError::InspectionFailed` and must write nothing.
- Lock order: `create.lock` before `<id>.lock`. Writers re-load the record under the lock.
- Event line format: `{"ts":<f64>,"actor":"…","type":"…","msg":"…"}\n`, one `O_APPEND` write, line ≤ 512 bytes (`msg` trimmed on a char boundary).
- Integration tests must skip (not fail) when `tmux` is not on `PATH`, and must create their state dirs under `/tmp` so the socket path stays short on macOS.

## Decisions the spec leaves open (locked here)

| Question | Decision |
|---|---|
| tmux session name | The record's `name`. `rename_session` renames both. Lookups never use the name; they use `@tx-id`. |
| Record file schema | `{"version":1,"id","name","parent","tags","cwd","created_at","ended_at","lifecycle","launch"}`; `lifecycle` as `"running"/"exited"/"stopped"`; `launch` tagged `{"kind":"agent",…}` / `{"kind":"process",…}`; `effort` as its name. Unknown `version` → `StoreError::Unreadable`. |
| Corrupt record during a scan | `list_sessions` / `refresh_all` fail with `Store(Unreadable{file})`. Nothing is hidden. `forget_session` still removes the file (it never loads it). |
| `resolve` tie-break | exact id → the single `Running` record with that name → the most recently created non-running one → `NotFound`. |
| `rename_session` / `set_session_tags` on a terminal record | Allowed (record only). `rename` on a `Running` record whose tmux session already vanished renames the record only; the next refresh marks it `Exited`. |
| `NameTaken` scope | Among `Running` records only. A `Stopped`/`Exited` record's name can be reused. |
| `stop_session` on a terminal record | `NotRunning`. On a `Running` record whose tmux session already vanished: record becomes `Exited` (truthful), returned as such. |
| `send_message` sender not found | `NotFound(sender id)`. Sender may be any lifecycle (a stopped agent's CLI call can still carry its id). |
| "no server" detection | stderr starts with `no server running on` or `error connecting to ` (both seen on tmux 3.6a). Anything else non-zero → `InspectionFailed{stderr}`. |
| `new-session` command | `-- <program> <args…>` passed as separate argv tokens (tmux ≥ 3.2 accepts `shell-command [argument …]`). No shell quoting. |
| Env on `new-session` | `-e KEY=VALUE` per pair, in merge order: `TX_SESSION_ID`, `TX_TMUX_SOCKET`, config env, option env, plan env; a later key replaces the earlier pair in place. Keys containing `=` or empty keys → `InvalidName`-style error: `CoreError::InvalidEnvKey(String)` (added to the enum; the spec's enum is a minimum). |
| Delivery pause | `pub const DELIVERY_PAUSE: Duration = 300 ms` in `messaging`; the same value `service.rs` uses today. |
| `WorkspaceAction` paths | `Write.path` and `Symlink.dst` resolve against `cwd`; `Symlink.src` is the link target, used verbatim (an adapter that wants a relative target writes one). `Write` creates parent dirs and overwrites. `Symlink` replaces an existing symlink, refuses an existing file/dir (`EngineError::Workspace`). Both refuse a resolved path that escapes `cwd` via `..` (`EngineError::Workspace`). |
| Profile `.local.md` | Base file = the **last** dir in `profile_dirs` holding `<NAME>.md`. Then every dir's `<NAME>.local.md`, in dir order, appended. |
| Skill grant syntax | Frontmatter line `skills: [a, b]` at any indent (covers both `tx:\n  skills: [...]` and the current top-level form). Skill dir = the **last** `skill_dirs` entry holding `<name>/`. Missing → `RoleError::UnknownSkill`. |
| Empty profile list | Allowed: empty text, file still written. |
| Profile file | `<state_dir>/profiles/<session id>.md`, written before `engine.launch`, removed if `create_session` later fails. |
| tmux.conf written on `open` | Only if absent: `# tx-core server config. Edit freely; the IDE may replace this file.\nset -s exit-empty on\nset -g history-limit 50000\n`. |
| Minimum tmux version | Not checked at `open` (would spawn tmux on every open). A `new-session -e` failure surfaces as `TmuxError::Failed` with tmux's stderr. |
| CLI | Crate `poc/tx-core-cli`, binary `txc`. Hand-rolled argv parsing, verbs: `create`, `ls`, `show`, `rename`, `tag`, `send`, `refresh`, `where`, `attach`, `stop`, `forget`. Registers `tx-engine-claude` and `tx-engine-codex`. |

## Review Focus

1. **A name that is valid for tx but special to tmux** (`-foo`, a name that is all digits like `3`, or one starting with `$`/`%`/`@`): `=name` exact targets and `--` before the command keep them safe. Test in Task 7: create `-x` and `3`, rename works, `has_session` lookups by `@tx-id` still resolve.
2. **Message text containing newlines, `;`, leading `-`, or non-ASCII:** must be typed verbatim (`send-keys -l --`), and the event log line must stay ≤ 512 bytes. Test in Task 9 (envelope + `pane_contents` assertion) and Task 4 (trim).
3. **A record on disk whose tmux session has a different name than the record** (renamed behind core's back): every operation locates by `@tx-id`, so `send_message`, `stop_session`, `get_execution_location` still work. Test in Task 11.
4. **Two sessions with the same `@tx-id`** (someone cloned a session with `new-session -t`): `LiveTable` must keep the first and ignore duplicates deterministically, never panic. Test in Task 6.
5. **`state_dir` on a filesystem without `flock` support or unwritable `locks/`:** `Lock(io::Error)` surfaces, no partial writes. Test in Task 5 (read-only locks dir → `Lock`).
