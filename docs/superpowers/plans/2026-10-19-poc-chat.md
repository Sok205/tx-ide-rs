# poc phase 3 — `chat` + `history` plugins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This plan has no per-task review loop; one whole-branch review runs after Task 6.

**Goal:** prefix+f forks the session in the firing pane, agent transcripts are mirrored under the state dir, and `fork` / `handover` / `rollover` / `resume` / `history` / `chat ls` work against `txc`. tx-core and the `hooks` plugin do not change.

**Architecture:** One crate `poc/plugins/chat` (`tx-chat`) carrying two plugins: `history` (transcript mirror, `history` listing) and `chat` (chat-id capture, chat ops, prefix+f). Neither uses a new core slot. Each plugin installs **its own** agent hook entries next to the `hooks` plugin's, with the same mechanism as `plugins/hooks/src/install.rs` but its own code and its own sidecar (D3). The hook commands are hidden verbs: `_chat-hook <event>` captures the payload's chat id and transcript path into `ext["chat"]`; `_history-ingest` records them into `ext["history"]` and re-runs itself detached to copy the bytes. Each plugin's bulk state lives in `<state_dir>/plugins/<id>/`, a path the crate builds itself from `core.config().state_dir` (D1). Forks and rollovers need engine-specific argv (D4). The crate builds it by calling the engine crates' pure `EngineAdapter::launch` as library code, then rewrites the args: `--fork-session` for claude, `fork` for codex. Abandoned handover / rollover ops are finished lazily at the start of every public chat verb, so no sweep slot is needed.

**Tech Stack:** Rust 2024 (1.92), tx-core, tx-ui, tx-engine-claude / tx-engine-codex (library use only), serde_json, uuid, libc (`setsid`, `mktime`), tmux 3.5, fzf.

**Spec:** `docs/superpowers/plans/2026-10-19-poc-port-roadmap.md` (Phase 3, D1–D7, Review Focus 1, 4, 5), `docs/superpowers/specs/2026-10-16-poc-plugins-design.md`, `docs/superpowers/specs/2026-10-19-poc-key-plugins-design.md` (D8–D12: resources, `keys/<id>.tmux`, `# keys:` line). Source on `main`, with line counts: `crates/tx/src/messages.rs` (1325), `history.rs` (707), `chat.rs` (1107), `verbs/chat.rs` (440), `verbs/fork_pane.rs` (99), `verbs/listing.rs` `History`/`Chat` + date parsing (~160 of 1040), `render.rs::render_history`/`render_chats` (~50), `engines/claude.rs` transcript/fork parts (~250 of 879), `engines/codex.rs` rollout/fork parts (~120 of 785), `engines/codex_rollout.rs` (242), `hooks.rs::capture_chat_ref`/`complete_pending`/`pending_index` (~90 of 310), `bin/tmux-fork-tx-session`.

## Global Constraints

- All work in `poc/`. `cd poc && cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all -- --check` must be green after every task. Every emitted script must pass `shellcheck`.
- **No change to `poc/tx-core/**` or `poc/plugins/hooks/**`.** Anything that seems to need one is solved inside `tx-chat` (or `tx-ui` for generic tmux / prompt helpers).
- The library never reads the environment. Only verbs (CLI-side code) read `TX_SESSION_ID`, `HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `TMUX_PANE` and `TX_CHAT_OP_*`.
- Every tmux call goes through `tx_ui::tmux::Ui` (`-S <socket> -f <conf>`). Never call bare `tmux`.
- Plugin data dirs: `history` → `<state_dir>/plugins/history/`, `chat` → `<state_dir>/plugins/chat/`. Create them lazily with mode 0755. Every JSON write is temp file + fsync + rename.
- D3: at run time, `chat` reads only `ext["history"]`, `ext["hooks"]` and `ext["spawn"]`, never writes them, and never calls `tx_hooks`. `history` reads `ext["chat"]` the same way. A crate-internal library call (chat ops calling the mirror) is allowed only after `core.plugin_status()` reports `history` active.
- Hidden verbs start with `_`. A usage error exits 2 with the usage on stderr. A missing session exits 1 with `<verb>: session '<token>' not found`. Hook verbs exit 0 on every "not ours" path and on bad payloads.
- Verb names, all checked against `RESERVED`: `fork`, `handover`, `rollover`, `resume`, `history`, `history-hooks`, `chat`, `_fork-pane`, `_chat-hook`, `_chat-op-finish`, `_chat-op-watch`, `_history-ingest`.
- Hook commands never exit 2: `<exe> <verb> … || exit 1`. `<exe>` is `current_exe()`, POSIX single-quoted.

## Review Focus

1. A record whose `ext["chat"]` or `ext["history"]` is malformed. `chat ls` must report it (exit 1, `chat ls: ext.chat of '<name>' is malformed: …`). `txc ls`, `txc show` and `txc _list` must still succeed. The hook verbs treat the value as empty and do not overwrite it. Owner: Task 3, test `malformed_ext_chat_is_reported_and_never_breaks_listing`.
2. Two `_history-ingest <id>` runs for the same chat at once, the case roadmap Review Focus 5 names. The per-(session, chat) flock must leave one complete, byte-identical copy and never two interleaved appends. Owner: Task 2, test `concurrent_ingests_leave_one_complete_copy`.
3. A transcript that shrank or was rewritten (compaction, `/clear` replaying into the same file) must be fully re-copied, never appended past a mismatch. Owner: Task 2, unit `shrink_or_window_mismatch_recopies`.
4. A hook fired with no `TX_SESSION_ID`, an unknown id, an empty or non-object payload, or a payload missing `session_id` / `transcript_path` must exit 0 and write nothing. Owner: Task 3, test `chat_hook_not_ours_or_bad_payload_writes_nothing`.
5. A handover whose watcher died must be finished exactly once by the next chat verb, and a live watcher's op must not be stolen. Owner: Task 4, test `an_abandoned_op_is_finished_once_by_the_next_chat_verb`.

Paths: `<chat_dir>/ops/<op>/{spec.json,claim/,done,watch.lock}`, `<chat_dir>/notes/<sid>/handover-<slug>.md` and `rollover-<n>.md`, `<chat_dir>/profiles/<new-name>.md`. Seed and distiller texts are main's `chat.rs` strings verbatim. The finish command embedded in them is `<'exe'> --state-dir <'state'> _chat-op-finish <'op'>`. The bundle pointer is `bundle_dir` when `history` is active (after a `Wait` ingest), else the live `ext.chat` ref's `transcript`.

Behaviour pinned:
- **fork**:
  1. The source needs an `agent_launch` and an `active_chat`; otherwise fail with `fork: '<name>' has no chat to fork`. The name is `next_free_name(name or "<src>-fork")`.
  2. Build the plan: `agent_plan(…, resume = chat id)`, then `fork_args`, then `apply_workspace(cwd, &plan.workspace)`.
  3. `create_session` with `LaunchOptions::process(plan.program, plan.args)`. The env is `plan.env`, the parent is the source, the tags are the source's tags, the cwd is the source's.
  4. `update_ext("chat")` to `{engine, launch: <source AgentLaunch>, chats: [{id: null, role: fork, how: "fork", since, origin: {session: src, chat: X}}]}`.
- **handover**:
  1. Name the worker `next_free_name(name or "<src>-handover")`.
  2. With `self_catch_up`, finish at once.
  3. Otherwise create a distiller: an Agent session named `next_free_name("<worker>-distill")` with the source's engine, `distiller(engine)` model and effort, `initial_prompt` = seed, and tags `[temporary, handover]`. Then `detach("_chat-op-watch", op)`.
  4. The finish creates the worker as an Agent with the source's `AgentLaunch` and `initial_prompt` = seed, parented to the source and carrying the source's tags. It writes a pending `{role: handover, how: "handover", origin}` ref.
- **rollover**:
  1. The target is the argument or `Ui::current_session_name`. The pane is `TMUX_PANE` when inside that session, else `display_message("#{pane_id}", name)`.
  2. Run a distiller as in handover (tags `[temporary, rollover]`), or, with `self_catch_up`, `detach("_chat-op-finish", op)`.
  3. The finish waits while `ext.hooks.state == "working"`, bounded by `timeout`. It does a `Wait` ingest when `history` is active, then `agent_plan(…, resume None, prompt seed)`.
  4. It runs `Ui::respawn_pane(pane, "env TX_SESSION_ID=… TX_TMUX_SOCKET=… TX_CORE_HOME=… <plan.env…> <shell-quoted program args>")`. It sets the current ref's `ended_at` and pushes a pending `{role: rollover, how: "rollover", origin: {session: self, chat: X}}` ref.
- **resume**:
  1. The target is any record with an `agent_launch` and an `active_chat`; otherwise exit 1 with `resume: '<name>' has no chat to resume`. The name is `--as` or the record's name. A Running record with that name exits 1 with `resume: a live session named '<n>' already exists — pass --as <new-name>`.
  2. The cwd is `--cwd` or the record's; a missing dir exits 1 with main's C8 text. Call `prepare_chat_for_cwd` when the cwd differs. Without a located transcript, print main's warning to stderr.
  3. `create_session` as an Agent with the `AgentLaunch` and `.resume(X)`, parented to the old record, with its tags.
  4. Write `ext.chat = {engine, chats: [{id: X, role: primary, how: "resume", since, origin: {session: old, chat: X}, transcript}]}`.
- Verb output (main's strings):
  - `Forked '<src>' → '<new>' (chat pending, cwd=<cwd>)`
  - `Handover '<src>' → worker '<w>' (<self-catch-up|distilling brief>; launches when ready)`
  - `Rollover scheduled (<self-catch-up|summarizing first>); the same session rotates onto a fresh chat when ready`
  - `Resumed '<old>' as '<new>' (chat <id8>, cwd=<cwd>)`
- Every public chat verb (`fork`, `handover`, `rollover`, `resume`, `chat ls`) first runs `finish_abandoned(WatchTimings::from_env())` and prints each failure to stderr as `chat: abandoned op <id>: <error>`. A failure there never changes the verb's exit code.
